The toggle

{% with view_mode="cards" %} {% include 'wise_core/components/_view_toggle.html' %} {% endwith %}

wise_core/components/_view_toggle.html renders two links to ?view=cards and ?view=table. It only needs one thing from the including template: a view_mode variable telling it which one is active.

The default is always cards
Don't decide this per model: every list page in this system writes request.GET.view|default:"cards", so a visitor lands on the card list wherever they are and the table stays one click away. A column-heavy, status-driven screen (an approvals queue) is still served by the same toggle — reach for ?view=table in a link to it, rather than flipping that page's default.

What's not handled

This is a small, self-contained pattern, not a new view mixin: it doesn't persist the choice across visits or preserve other query params (filters, page) when switching - the same tradeoff _pagination.html already makes with its own query string. If your project needs either, wrap request.GET in a small templatetag that copies it forward with one key replaced.
