An empty table is the one screen a visitor can reach with nothing to read and nothing to click, so it carries the way out: a line saying why it is empty and the button that fixes it — New record when there is nothing yet, Clear filters when the records exist but the filters hid them. {% endblock %} {% block doc_body %}

Use cases

  • The {% templatetag openblock %} empty {% templatetag closeblock %} branch of any list — inside a <td colspan="N"> for a data table, on its own in a card list.
  • A child tab with no records under this parent yet (a category with no products), where the create button has to carry the parent along.
  • A filtered list that matched nothing — a different message, and a way back to the unfiltered list rather than a create button.
  • Any page or panel with nothing to show, through the {% templatetag openblock %} empty_state {% templatetag closeblock %} tag — a first-run dashboard, an empty inbox, a search that found nothing.
  • Not a loading state: a list still fetching shows a spinner, because "nothing here" and "nothing yet" mean opposite things to whoever is waiting.
  • Not an error state: a failed request is a callout or a toast — telling someone their data doesn't exist when the query merely failed is worse than saying nothing.

Why the two states differ
"Create the first product" under an active filter invites a duplicate: the record the visitor is about to add may already exist three rows up, hidden by a filter they forgot they set. So a filtered-empty list offers Clear filters instead, pointing at request.path — the same list with the query string dropped.

Anywhere else: the tag

_no_data.html reads a list view's context. For everything else — a page, a panel, a search box that found nothing — use Lumen's EmptyState directly. The tag's body is the next step, usually one button.

Two illustrations, no more
empty (a stacked panel with a dot) is for nothing-yet and search (a panel under a magnifier) for nothing-found. They are drawn from tokens, so the accent color, theme and dark mode all apply. For your own picture pass markup you already made safe as illustration; None or "none" drops it. Not for errors: a failed request is a callout.

Writing the copy

  • First run: tell people what the space is for and how to start. No results: say what was searched and how to widen it.
  • Keep the title under eight words. Name the thing that's missing ("No products yet"), not the container ("This table is empty"). The visitor knows they're looking at a table.
  • One sentence under the title, at most. It says what would put something here — not how the feature works.
  • One primary action. A second button turns a dead end into a decision, and the whole point of this block is that there is nothing to decide.
  • No apology, no exclamation mark. An empty list is the normal first state of every list ever created.
