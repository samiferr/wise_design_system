Use cases

  • Any list view backed by Django's Paginator - a WiseListView subclass gets this automatically once paginate_by is set.
  • Paging through search results, a data table, or a card list that returns more rows than fit on one page.
  • Preserving the view mode, sort and filters while moving between pages - every link re-emits the existing query string.
  • Not something to hand-write per page - the partial handles the page-number window, the ends and the summary.

Appearance

A nav with a chevron-only Previous and Next (disabled in place at the ends, so the control never changes width), numbered pill buttons, and ellipses where a run of pages is elided. The current page is aria-current="page" and filled with neutral-background. Beside it, a "Showing 21–40 of 312" summary tells people where they are.

What it needs

page_obj — the standard name Django's ListView puts in the context. WiseListView supplies it as soon as you set paginate_by. The partial also carries every other query parameter across page links, so paging through filtered or sorted results does not silently reset them. 

{% filter force_escape %}{% verbatim %}class CategoryListView(WiseListView):
    model = Category
    filterset_class = CategoryFilter
    template_name = 'showcase/category/list.html'
    paginate_by = 10{% endverbatim %}{% endfilter %}

See it against a real queryset on Categories.

Windowing and short lists

Up to seven pages are all shown. Beyond that the pager shows the first and last page and the current page with one page either side, and an ellipsis for each elided run - the page_window filter works this out, exactly as Lumen's Pagination does. Lumen advises against pagination for fewer than three pages; because a Django Paginator has already split the rows, a list of two pages keeps its buttons (otherwise page 2 is unreachable), while a list that fits one page shows only the summary.

Preserving other query parameters

Every link is built by the page_url tag, which merges the new page number into the current request.GET, so ?view=table, the sort and the active filters all survive paging. Use it for any pager of your own: 

{% filter force_escape %}{% verbatim %}{% load wise_tags %}
{% for item in page_obj|page_window %}
    {% if item is None %}…{% else %}{{ item }}{% endif %}
{% endfor %}{% endverbatim %}{% endfilter %}

Large tables

Paginator issues a COUNT(*) per page, which gets expensive on very large tables. If that becomes a problem, keyset ("seek") pagination — WHERE id < last_seen ORDER BY id LIMIT n — is the usual answer; the same .pagination-link markup still applies.
