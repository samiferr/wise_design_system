Expand and collapse, keyboard support and the open/closed state are all native — there is no JavaScript and no ARIA to add. {% endblock %} {% block doc_body %}

Use cases

  • An FAQ list or help section where only a few answers need to be open at once.
  • Progressive disclosure of secondary settings or advanced options that most users won't need to see by default.
  • Grouping long-form content (a detail page's optional sections) so the page isn't overwhelming on first load.
  • Anywhere expand/collapse needs correct keyboard support and ARIA for free, with zero JavaScript.

The name attribute on <details> is recent. Where it is unsupported the accordion still works — sections just open independently, which is a reasonable fallback.

Accordion vs. tabs vs. tree

UseWhen
AccordionSections of one page; several can be open; content is on the page already.
TabsAlternative views of one record, each with its own URL.
TreeHierarchical navigation, arbitrarily deep.

Reference

ClassUse
accordionBordered container around the items.
accordion-itemOn each <details>.
accordion-chevronIcon in the summary; rotates when open.
accordion-contentThe revealed panel.
