A parent usually has more than one kind of child, so its page is a tabbed one: the parent's own overview first, then a tab per child model. The parent's primary key lives in the URL, which is what keeps every child view scoped, secure, and able to send the visitor back where they came from. {% endblock %} {% block doc_body %}

The tab bar

One bar, rendered identically on the parent's overview and on every page of every child — list, create, edit, delete, detail. A visitor two clicks into a child form still sees whose child it is and can switch to a sibling tab in one click.

The URL shape

Nest the child routes under the parent. This single decision does most of the work: the parent is always available, the queryset is always scoped, and "back" is always obvious. 

{% filter force_escape %}{% verbatim %}urlpatterns = [
    path('products//', ProductDetailView.as_view(), name='product_detail_view'),

    # children, always under their parent
    path('products//variants/',
         ProductVariantListView.as_view(),   name='product_variant_list_view'),
    path('products//variants/create/',
         ProductVariantCreateView.as_view(), name='product_variant_create_view'),
    path('products//variants//',
         ProductVariantDetailView.as_view(), name='product_variant_detail_view'),
    path('products//variants//update/',
         ProductVariantUpdateView.as_view(), name='product_variant_update_view'),
    path('products//variants//delete/',
         ProductVariantDeleteView.as_view(), name='product_variant_delete_view'),

    # ... the same five for reviews
]{% endverbatim %}{% endfilter %}

Declare the tabs once

The bar is a Python list, handed to the parent's detail view and to every child view under it, so none of them can drift apart. Each tab reverses its own URL against the parent, checks its own permission, and reads its own count. 

{% filter force_escape %}{% verbatim %}from wise_core.mixins import ChildTab

PRODUCT_TABS = [
    ChildTab.overview('Overview', 'product_detail_view', icon='info'),
    ChildTab('Variants', 'product_variant_list_view',
             model=ProductVariant, icon='tag', count='variants'),
    ChildTab('Reviews', 'product_review_list_view',
             model=ProductReview, icon='star', count='reviews'),
]{% endverbatim %}{% endfilter %}
ArgumentWhat it does
labelThe tab's text.
url_nameThe child's list view, reversed with the parent's pk.
modelThe child model — the tab is hidden from a user without view_<model>.
permissionAn explicit codename instead of the derived one. Neither set means always visible.
iconA Lucide icon before the label.
countThe badge: a related manager name ("variants"), an attribute/annotation, or a callable.
matchURL-name prefix that lights the tab up. Defaults to url_name minus a trailing _list/_list_view, so the child's create/edit/delete pages stay on their own tab.
url_kwargThe kwarg carrying the parent's pk — parent_pk, or pk for ChildTab.overview().

The views

WiseParentDetailView is the overview tab. Each child gets the five WiseParentDetailChild*Views, which resolve the parent from the URL, scope every query to it, and put it in the context as parent_object. 

{% filter force_escape %}{% verbatim %}class ProductDetailView(WiseParentDetailView):
    model = Product
    child_tabs = PRODUCT_TABS
    template_name = 'shop/product/detail.html'


class ProductVariantListView(WiseParentDetailChildListView):
    model = ProductVariant
    parent_model = Product
    parent_field = 'product_id'                        # the FK back to the parent
    child_tabs = PRODUCT_TABS
    template_name = 'shop/product/variant/list.html'


class ProductVariantCreateView(WiseParentDetailChildCreateView):
    model = ProductVariant
    parent_model = Product
    parent_field = 'product_id'
    child_tabs = PRODUCT_TABS
    child_list_url_name = 'product_variant_list_view'  # back, Cancel and the redirect after saving
    form_class = ProductVariantForm                    # which has no `product` field
    template_name = 'shop/product/variant/form.html'{% endverbatim %}{% endfilter %}
{% lucide "alert-triangle" size=16 cls="callout-icon" %}
The parent is never a form field
WiseParentDetailChildCreateView sets parent_field from the URL before saving. Exposing a parent select on the child's form instead would let anyone move the record under a parent they picked — and the queryset scoping in get_queryset() is what makes /products/1/variants/99/ 404 when variant 99 belongs to another product, rather than quietly editing it.

The templates

Five templates in wise_core/generic/ cover the whole group. They all extend parent_base_generic.html — the chrome holding the parent's action bar, name and tab bar — and each fills in one page's body.

TemplatePage
parent_detail_generic.htmlThe parent's overview tab.
parent_child_list_generic.htmlOne child model's rows.
parent_child_form_generic.htmlAdd or edit a child.
parent_child_confirm_generic.htmlDelete a child.
parent_child_detail_generic.htmlOne child record.

They reuse the block names of their flat counterparts — detail_rows, list_body/card_item, form_fields, confirm_rows — so moving a page into a tabbed group means changing which template it extends, not rewriting it.

Deleting the parent

Say what will be destroyed. on_delete=CASCADE quietly removing dozens of children is the kind of surprise that costs trust.

Editing children inline

A tab per child model is the right shape when children are records in their own right. When they are small and always edited together — order lines, say — a Django inlineformset_factory on the parent's own form avoids a page per row. 

{% filter force_escape %}{% verbatim %}VariantFormSet = inlineformset_factory(
    Product, ProductVariant, form=ProductVariantForm, extra=1, can_delete=True,
)

class ProductUpdateView(WiseUpdateView):
    def get_context_data(self, **kwargs):
        context = super().get_context_data(**kwargs)
        context['formset'] = VariantFormSet(self.request.POST or None, instance=self.object)
        return context

    def form_valid(self, form):
        formset = VariantFormSet(self.request.POST, instance=form.instance)
        if not formset.is_valid():
            return self.form_invalid(form)
        response = super().form_valid(form)
        formset.save()
        return response{% endverbatim %}{% endfilter %}
