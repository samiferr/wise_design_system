Use cases

  • Any single-line text field inside a Django form - name, reference, email, phone.
  • A standalone control that needs no label/help/error treatment of its own, like an inline search box or a filter row.
  • Any HTML5 text-like input type (email, url, tel, search, password) - one class covers all of them, since the browser supplies the keyboard and validation per type.
  • Inside a real form, prefer letting _form_fields.html render the field automatically rather than writing the input tag by hand.

{% filter force_escape %}{% verbatim %}Use the Wise Design System's Input for text fields. Rules:
- Standalone control with no label needed: . Use `.input` directly only for a control that doesn't need its own label/help/error treatment - an inline search box, a filter row.
- Inside a real form, do NOT write  by hand - let wise_core/components/_form_fields.html render every BoundField from the form, so it automatically gets its label (.form-label), help text, required marker, and error list wrapped in .form-field / .form-field-error.
- Size modifiers: input-sm, input-lg (default otherwise) - same modifiers apply to .select.
- One class covers every text-like input type (text, email, url, tel, search, password) - the type attribute, not a different CSS class, is what changes the browser's keyboard and built-in validation.
- To attach a prefix/suffix (currency symbol, unit, icon, inline button), wrap the input in `.input-group` with an `.input-group-addon` sibling rather than positioning your own absolutely-placed icon inside the input.{% endverbatim %}{% endfilter %}
