Use cases

  • The persistent desktop navigation column for any authenticated app built on wise_core's base.html - included automatically, not something you build per project.
  • Grouping a project's models/sections into labeled navigation groups (e.g. "Reference Data", "Purchasing", "Sales").
  • Highlighting the current section so the user always knows where they are in the app.
  • Not the place to add ad-hoc links by hand-editing HTML - configure the WISE_NAV_SECTIONS setting instead so the sidebar stays data-driven.

Supplying wise_nav_sections

A context processor in your own project — nav_menu.html just reads it, it doesn't build it:

{% filter force_escape %}{% verbatim %}WISE_NAV_SECTIONS = [
    {
        'title': 'Catalog',
        'items': [
            {'label': 'Categories', 'url_name': 'category_list_view', 'icon': 'tag', 'match': 'category'},
            {'label': 'Products', 'url_name': 'product_list_view', 'icon': 'clipboard-list', 'match': 'product'},
        ],
    },
]{% endverbatim %}{% endfilter %}

Desktop vs. mobile

base.html renders this same nav_menu.html twice: once inside a fixed md:sticky column for desktop, and once inside wise_core/components/sidebar.html — a full-screen overlay toggled by the topbar's hamburger button — for mobile. The menu markup itself doesn't change between the two.

{% filter force_escape %}{% verbatim %}Use the Wise Design System's Sidebar by configuring WISE_NAV_SECTIONS in your Django settings - do not hand-edit the sidebar markup. Rules:
- wise_core/base.html already includes the sidebar (via nav_menu.html) for every authenticated page - you get it for free once wise_core is installed and a user is logged in.
- Define your app's navigation entirely as data in settings.py:
  WISE_NAV_SECTIONS = [
      {'title': 'Reference Data', 'items': [
          {'label': 'Departments', 'url_name': 'department_list_view', 'icon': 'building-2', 'match': 'department_'},
      ]},
  ]
- Each item's `match` is the prefix of the current URL name that marks that link `.selected` - choose the prefix shared by every view for that model (list/detail/create/update/delete) so the whole group highlights consistently. It is anchored at the start of the name, so a child route nested under another model (`category_product_list_view`) highlights its own parent section rather than two at once.
- `icon` is a Lucide icon name, rendered via the lucide template tag - keep icon choices consistent across sections (e.g. always building-2 for org-type entities).
- The signed-in user's name is pinned to the bottom of the sidebar automatically from request.user - nothing to configure there.
- To change which sections/links appear, edit WISE_NAV_SECTIONS in settings.py, never wise_core/templates/wise_core/components/nav_menu.html directly, since that file is shared, vendored package code.{% endverbatim %}{% endfilter %}
