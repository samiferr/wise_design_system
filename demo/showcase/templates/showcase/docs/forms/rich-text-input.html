Use cases

  • Content that genuinely needs structure - headings, bold/italic, bullet lists - like a notes field, a product description, or published copy.
  • A TextField that stores HTML, rendered back with the same formatting the author applied.
  • Editorial or CMS-style content where a plain textarea would lose the author's intended structure.
  • Not for short, plain values or anything you don't want to sanitize as HTML - use a plain Textarea for that; it's cheaper and easier to keep safe.

Rendering the stored HTML

{% lucide "alert-triangle" size=16 cls="callout-icon" %}
Never render it with |safe unsanitized
The field contains HTML supplied by whoever filled the form. Piping it straight through |safe is a stored-XSS vulnerability. Sanitize on the way in, with an allowlist, and treat the stored value as untrusted until you have.

import nh3

def clean_notes(self):
    return nh3.clean(
        self.cleaned_data["notes"],
        tags={"p", "br", "strong", "em", "u", "ol", "ul", "li", "a", "h2", "h3", "blockquote"},
        attributes={"a": {"href", "title", "rel"}},

{% filter force_escape %}{% verbatim %}Use the Wise Design System's Rich Text Input (wise_richtext app) - a Quill-backed editor posting HTML into an ordinary TextField. Rules:
- Add 'wise_richtext' to INSTALLED_APPS. In forms.py: from wise_richtext.widgets import RichTextInputWidget; description = forms.CharField(widget=RichTextInputWidget()) backing a model TextField.
- The field stores real HTML - always render it with Django's own HTML-escaping-aware tools; if you mark it safe for display (e.g. |safe or format_html), you MUST sanitize the stored HTML (e.g. with bleach) before ever trusting user-submitted rich text, since Quill's client-side editor does not guarantee the HTML it posts is safe to render unsanitized.
- Only use this where the content genuinely needs structure - for anything plainer (a short note, a single-line description), a plain Textarea is cheaper to store, render, and sanitize, and carries none of the stored-XSS risk that comes with storing arbitrary HTML.
- Do not attempt to hand-roll a WYSIWYG editor or pull in a different JS rich-text library - Quill is already vendored and wired to post into a plain form field with no extra JS to write.{% endverbatim %}{% endfilter %}
