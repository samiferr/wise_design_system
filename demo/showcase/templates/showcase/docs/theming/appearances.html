How it works

  1. wise_core.middleware.AppearanceMiddleware picks the appearance for each request and puts it on request.appearance. It checks, in order: ?appearance=, the cookie, the session, your WISE_APPEARANCE_RESOLVER, then WISE_DEFAULT_APPEARANCE.
  2. The wise_core.context_processors.appearance context processor exposes it, and wise_core/base.html renders <html data-appearance="…"> on the server.
  3. tokens.css imports appearances/tangerine.css, which re-points the system tokens under :root[data-appearance="tangerine"]. Component class names don't change, so every template works in both appearances.
  4. wiseSetAppearance() switches in the browser. A POST to {% url 'wise_set_appearance' %} does the same without JavaScript.

Set it up

{% filter force_escape %}{% verbatim %}# settings.py
MIDDLEWARE = [
    # ...
    'django.contrib.sessions.middleware.SessionMiddleware',
    'wise_core.middleware.AppearanceMiddleware',
    # ...
]

TEMPLATES[0]['OPTIONS']['context_processors'] += [
    'wise_core.context_processors.appearance',
]

WISE_APPEARANCES = [('lumen', 'Lumen'), ('tangerine', 'Tangerine')]   # the default
WISE_DEFAULT_APPEARANCE = 'lumen'

# urls.py
urlpatterns += [path('wise/', include('wise_core.urls'))]   # wise_set_appearance{% endverbatim %}{% endfilter %}
