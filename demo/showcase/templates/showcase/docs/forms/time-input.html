Use cases

  • A time-of-day field - appointment time, opening hours, a shift start/end.
  • A TimeField in a Django form where the native browser time picker is enough.
  • Any field where the display format should follow the user's locale (12h vs 24h) while the server always gets a consistent 24-hour value.
  • Not for a full datetime - pair this with a Date Input for separate date+time fields, or use a DateTimeField widget if the model field is a single DateTimeField.

Time zones

{% lucide "alert-triangle" size=16 cls="callout-icon" %}
A TimeField has no date and therefore no timezone — it cannot be converted. For a moment in time use DateTimeField and let Django store UTC. Keep TimeField for wall-clock values like opening hours, which genuinely are "09:00 local, whatever local means today".
