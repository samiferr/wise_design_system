There is no npm package to depend on at runtime and no JS bundler — Tailwind's CLI compiles one stylesheet, and Django serves it as an ordinary static file. {% endblock %} {% block doc_body %}

1. Add the apps

Copy wise_core/ (and optionally wise_autocomplete/ and wise_richtext/) next to your own apps, then register them. wise_core is the only required one. 

{% filter force_escape %}{% verbatim %}INSTALLED_APPS = [
    # ...
    'django.contrib.humanize',   # used by some generic templates
    'django_filters',            # required by WiseListView's filtering
    'rest_framework',            # only if you use AutocompleteInputWidget

    'wise_core',
    'wise_autocomplete',         # optional
    'wise_richtext',             # optional
]{% endverbatim %}{% endfilter %}

2. Register the context processor

wise_core.context_processors.nav feeds the sidebar menu from a plain setting. Skip it only if you never render nav_menu.html. 

{% filter force_escape %}{% verbatim %}TEMPLATES = [{
    'BACKEND': 'django.template.backends.django.DjangoTemplates',
    'APP_DIRS': True,
    'OPTIONS': {'context_processors': [
        'django.template.context_processors.request',   # required
        'django.contrib.auth.context_processors.auth',
        'django.contrib.messages.context_processors.messages',
        'wise_core.context_processors.nav',
    ]},
}]{% endverbatim %}{% endfilter %}

3. Build the stylesheet

tokens.css is a partial, not an entry point — it has no @import "tailwindcss" and no @source of its own, because those depend on where your templates live. Your project supplies an entry file that imports Tailwind, tells it where to look for class names, then pulls in the design system's tokens. Concretely, that's four steps:

3a. Create the entry stylesheet

Create static_src/input.css (any path works — this is just the file you'll point the Tailwind CLI at in step 3c) with three things in this order: the Tailwind import, an @source line for every template directory that uses utility classes, then the tokens import last. 

{% filter force_escape %}{% verbatim %}/* static_src/input.css */
@import "tailwindcss";

/* Tell Tailwind where to scan for class names - including every wise_* app,
   since their component markup uses utility classes too. */
@source "../myapp/templates";
@source "../../wise_core/templates";
@source "../../wise_autocomplete/templates";
@source "../../wise_richtext/templates";

@import "../../wise_core/static/wise_core/css/tokens.css";{% endverbatim %}{% endfilter %}
Forgetting an @source line is the single most common setup mistake: the build succeeds, but any utility class used only in that directory is tree-shaken out and the page renders unstyled.

3b. Install the Tailwind CLI

{% filter force_escape %}{% verbatim %}npm install -D @tailwindcss/cli tailwindcss{% endverbatim %}{% endfilter %}

3c. Compile it

Run once for a production build, or add --watch while developing so the CSS recompiles as you edit templates. 

{% filter force_escape %}{% verbatim %}# one-off build
npx tailwindcss -i ./static_src/input.css \
                -o ./wise_core/static/wise_core/css/tailwind.css --minify

# rebuild automatically while you work
npx tailwindcss -i ./static_src/input.css \
                -o ./wise_core/static/wise_core/css/tailwind.css --watch{% endverbatim %}{% endfilter %}

Point {% templatetag openblock %} load static {% templatetag closeblock %} / your base template at that output file — wise_core/base.html already does this for you if you extend it in the next step.

3d. Customize colors, or build a theme of your own

Never edit tokens.css itself — that file belongs to the design system and gets overwritten on upgrade. Instead, add your own @theme block to input.css, after the tokens.css import: Tailwind v4 merges @theme blocks by variable name, so whichever one is imported last wins. 

{% filter force_escape %}{% verbatim %}/* static_src/input.css */
@import "tailwindcss";
@source "../myapp/templates";
@source "../../wise_core/templates";
@import "../../wise_core/static/wise_core/css/tokens.css";

/* Imported AFTER tokens.css, so these override it. */
@theme {
    --color-brand-500: #7c3aed;
    --color-brand-600: #6d28d9;
    --color-brand-700: #5b21b6;
    --color-action-500: #7c3aed;
    --color-action-600: #6d28d9;
    --color-action-700: #5b21b6;
}{% endverbatim %}{% endfilter %}

Adding a brand-new theme (as opposed to retuning the default one) works the same way, but with an attribute selector instead of a bare @theme block — add this and wiseSetTheme('sepia') switches to it with no other wiring needed: 

{% filter force_escape %}{% verbatim %}:root[data-theme="sepia"] {
    --color-page: #f4ecd8;
    --color-panel: #fbf6ea;
    --color-gray-900: #3b2f1c;
}{% endverbatim %}{% endfilter %}

Rebuild (step 3c) after any token change — Tailwind has to re-scan and re-emit tailwind.css before the new values show up. For rounded corners, overriding a component's own CSS rule, and checking contrast when you retune a color ramp, see Customizing & Theming.
