Supplying the options

Point data-list at a <datalist> elsewhere on the page; the widget seeds itself from its <option> values. The datalist is only a data carrier here — the visible panel is the widget's own. 

{% filter force_escape %}{% verbatim %}from wise_autocomplete.widgets import AutoSuggestInputWidget

tag = forms.CharField(
    widget=AutoSuggestInputWidget(attrs={"data-list": "tag_suggestions"}),
){% endverbatim %}{% endfilter %}
{% filter force_escape %}{% verbatim %}
    {% for tag in available_tags %}{% endfor %}
{% endverbatim %}{% endfilter %}

Or assign the array directly

{% filter force_escape %}{% verbatim %}document.getElementById('id_tag').arr = ['Draft', 'Pending', 'Confirmed']{% endverbatim %}{% endfilter %}

When to use which

UseWhen
ComboboxShort static list, browser-native popup is fine.
Auto SuggestKnown list, but you want a styled panel and keyboard navigation.
AutocompleteOptions live in a database table and must be searched server-side.
{% lucide "info" size=16 cls="callout-icon" %}
Every option ships in the HTML, so the page grows with the list. Past a few hundred entries that is the wrong trade — switch to Autocomplete.

Reference

AttributeUse
data-listId of a <datalist> to seed options from.
data-parentId of a parent field's input, to scope suggestions.
.arrJS property on the input; the option array, if set directly.
