The feedback matters more than the copy itself — without it, users click repeatedly because nothing appeared to happen. A text label, not an icon, so the confirmation reads at a glance instead of asking someone to recognize what a check mark meant. {% endblock %} {% block doc_body %}

Use cases

  • Copying a code sample, API key, invite link, or token so the user doesn't have to select the text by hand.
  • Confirming that a click actually did something - any copy action needs visible feedback, or users click repeatedly.
  • Copying either a fixed string or the text of another element on the page (a 
     block, a generated value).
  • Not for a value the user is expected to edit - this is copy-only feedback, not a form control.

Markup

Both states ship in the markup and CSS shows one at a time — the same approach the theme toggle uses. The script only toggles a class, so there is no innerHTML rewriting. Give .copy-button-done the widest label you'll show (usually "Copied") so the button reserves that width up front and doesn't reflow when the state switches.

How it works

common.js binds one delegated listener, so buttons added to the page later (in a drawer, a dialog, an HTMX swap) work without re-binding. navigator.clipboard needs a secure context; over plain HTTP the handler falls back to selecting the text so the user can copy manually. 

{% filter force_escape %}{% verbatim %}document.addEventListener('click', function (e) {
    var button = e.target.closest('.copy-button')
    if (!button) return
    var text = button.dataset.copy
    if (!text && button.dataset.copyTarget) {
        var el = document.querySelector(button.dataset.copyTarget)
        text = el ? (el.innerText || el.textContent) : ''
    }
    wiseCopy(button, text)
}){% endverbatim %}{% endfilter %}
