What it needs

page_obj — the standard name Django's ListView puts in the context. WiseListView supplies it as soon as you set paginate_by. The partial also carries the current search parameter across page links, so paging through filtered results does not silently reset the filter.

    model = Category
    filterset_class = CategoryFilter
    template_name = 'showcase/category/list.html'
    paginate_by = 10{% endverbatim %}{% endfilter %}

Preserving other query parameters

{% lucide "alert-triangle" size=16 cls="callout-icon" %}
If you add your own query parameters — a sort column, a tab — carry them onto the page links too, or page 2 will silently drop them. A small template filter that merges the current request.GET with the new page number is the tidiest fix. 
{% filter force_escape %}{% verbatim %}@register.simple_tag(takes_context=True)
def query_replace(context, **kwargs):
    """{% query_replace page=3 %} -> keeps every other param intact."""
    query = context['request'].GET.copy()
    for key, value in kwargs.items():
        query[key] = value
    return query.urlencode(){% endverbatim %}{% endfilter %}

Large tables

Paginator issues a COUNT(*) per page, which gets expensive on very large tables. If that becomes a problem, keyset ("seek") pagination — WHERE id < last_seen ORDER BY id LIMIT n — is the usual answer; the same .pagination-link markup still applies.
