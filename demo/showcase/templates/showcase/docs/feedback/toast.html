The Django way

_messages.html is included once in base.html, so every page already renders whatever messages are pending. You only emit them. 

{% filter force_escape %}{% verbatim %}from django.contrib import messages

def publish(request, pk):
    product = get_object_or_404(Product, pk=pk)
    product.publish()
    messages.success(request, 'Product "%s" published.' % product.name)
    return redirect(product.get_absolute_url()){% endverbatim %}{% endfilter %}

The CRUD mixins do it for you from a success_message attribute — create or edit a Category to see one fire. 

{% filter force_escape %}{% verbatim %}class CategoryCreateView(WiseCreateView):
    model = Category
    form_class = CategoryForm
    success_message = 'Category "%(name)s" created.'{% endverbatim %}{% endfilter %}

    Auto-dismiss and accessibility

    {% lucide "alert-triangle" size=16 cls="callout-icon" %}
    Don't put irreplaceable information in a toast
    It disappears after six seconds and cannot be recalled. Validation errors belong on the field; anything the user may need to act on later belongs in the page. Add role="status" so screen readers announce it, and give error toasts no auto-dismiss at all.
