What the visitor sees

A record that other records still point at through on_delete=PROTECT (or RESTRICT) cannot be deleted. Instead of a server error after pressing Delete, the confirm page says so up front: which kinds of record are in the way, how many, and - for kinds the visitor may view - the first few as links. There is no Delete button to press.

WiseDeleteView (and so every WiseParentDetailChildDeleteView) includes ProtectedDeleteMixin. On GET it asks Django's deletion collector what deleting the record would run into - without deleting anything - and hands the template delete_blockers; the stock confirm_generic.html / parent_child_confirm_generic.html render the list in place of the warning. A POST that reaches the database's refusal anyway (a record added in between) is caught and shows the same page. 

{% filter force_escape %}{% verbatim %}class UnitDeleteView(WiseDeleteView):
    model = MeasureUnit
    protected_message = _('This unit cannot be deleted: products use it.')   # optional
    blocker_sample_size = 5                                                    # records named per kind{% endverbatim %}{% endfilter %}

The default sentence names the record and, when the model has an is_active field, suggests deactivating it instead. A blocking kind with no page of its own (an order line, whose order is what a person opens) overrides get_blocker_url(record).
