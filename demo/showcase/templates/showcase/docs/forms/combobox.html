The widget derives the <datalist> id from the field's own id, so two comboboxes on one page never collide.

Choosing between the three

This system has three "type to choose" controls. They are not interchangeable:

ControlOptions come fromNew values?Use when
ComboboxInline <datalist>Yes A short, static list where free text is legitimate.
Auto Suggest A JS array on the pageYes The list is known up front but needs richer filtering than the browser's.
Autocomplete A DRF endpointNo — picks a record The list is a database table, too big to inline.

Limits of datalist

{% lucide "alert-triangle" size=16 cls="callout-icon" %}
The popup's appearance is entirely the browser's — it cannot be styled, and it varies between them. You also cannot show a label distinct from the submitted value. When either matters, move to Auto Suggest or Autocomplete, which render their own panel with .autocomplete-panel.

Suggestions from the database

Fine for a bounded list — existing tag names, say. Above a few hundred options, inlining them into every page render stops being reasonable; switch to Autocomplete. 

{% filter force_escape %}{% verbatim %}class ProductForm(forms.ModelForm):
    def __init__(self, *args, **kwargs):
        super().__init__(*args, **kwargs)
        self.fields["supplier"].widget = ComboboxInput(
            choices=Product.objects.values_list("supplier", flat=True)
