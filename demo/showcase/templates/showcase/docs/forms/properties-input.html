Each known key is an ordinary Django form field on its own row, rendered by that field's widget and validated by its clean(); free-form keys can be added and removed. cleaned_data is a plain dict, ready to save. {% endblock %} {% block doc_body %}

Use cases

  • Product specifications, device settings or custom attributes that vary per record and live in one JSONField.
  • A handful of typed keys (a number with a minimum, a choice, a date) plus room for keys nobody planned for.
  • Metadata a user edits by hand where a raw JSON textarea would be error-prone.
  • Not for data you filter, sort or join on all the time - give that its own model column.

The field

{% filter force_escape %}{% verbatim %}from django import forms
from wise_core.widgets import PropertiesField, SwitchInput

class Product(models.Model):
    specs = models.JSONField(default=dict, blank=True)

class ProductForm(forms.ModelForm):
    specs = PropertiesField(
        schema={
            "weight_kg": forms.DecimalField(label="Weight (kg)", min_value=0),
            "color": forms.ChoiceField(choices=COLORS),
            "released": forms.DateField(required=False, widget=forms.DateInput(attrs={"type": "date"})),
            "fragile": forms.BooleanField(required=False, widget=SwitchInput),
        },
        allow_extra=True,       # let users add keys outside the schema
    )

    class Meta:
        model = Product
        fields = ["name", "specs"]{% endverbatim %}{% endfilter %}

Declare the field on the form (a ModelForm would otherwise pick Django's raw JSON textarea for a JSONField). {% verbatim %}{{ form.media }}{% endverbatim %} isn't needed: the add/remove script ships inline with the widget.

Validation

Every schema row is cleaned by its own field, so a property validates exactly like a top-level field: required, min_value, max_length, choices, validators. The errors are collected under the one field, each prefixed with the property's label, and only the rows that failed turn red. What gets saved

Values are turned into JSON-native data with DjangoJSONEncoder: dates and times become ISO strings, Decimal and UUID strings, a model choice its primary key. Empty optional keys are left out. For the example above, filled in correctly: 

{{ cleaned_json }}

Free-form values are typed by JSONValueField: 4, true, [1, 2] are stored as JSON, anything else (FR, 01234) as text, and "4" (quoted) forces a string. Stored values are shown the same way, so re-saving a record never changes a value's type.

{% filter force_escape %}{% verbatim %}Use the Wise Design System's Properties Input to edit a models.JSONField as key/value rows. Rules:
- In forms.py: from wise_core.widgets import PropertiesField; declare it on the form (not in Meta.widgets): specs = PropertiesField(schema={...}, allow_extra=True). The model field is models.JSONField(default=dict, blank=True).
- schema maps each known key to an ordinary django.forms field (DecimalField, ChoiceField, DateField, BooleanField(widget=SwitchInput), URLField, ModelChoiceField...). Do not write custom validation for those keys - the field's own clean() does it.
- Free-form keys need allow_extra=True; tune them with key_field= (e.g. forms.SlugField()), extra_field= (default JSONValueField: typed JSON, else text) and max_extra=.
- cleaned_data[name] is a plain JSON-native dict (dates are ISO strings, Decimals strings, model choices pks). Save it as is.
- Render it with the shared _form_fields.html partial (or inside a .form-field); never hand-write the rows, the add button or the script.{% endverbatim %}{% endfilter %}
