Badges describe state the system knows; a tag labels a value a user supplied. {% endblock %} {% block doc_body %}

Use cases

  • Showing a record's workflow state at a glance in a list, table, or detail panel (draft/pending/confirmed/cancelled).
  • An unread or pending-action count on an icon button, like a filter button with active filters.
  • A short, styled label attached to a count already shown elsewhere, e.g. next to a nav item.
  • Anywhere the label describes state the system computed - for a value the user typed themselves, use a tag instead.

Workflow states

The grey/orange/green/red/blue set is deliberately not named "success"/"error" — that keeps it mappable onto any domain's status field without the names lying about what they mean.

{% filter force_escape %}{% verbatim %}class Order(models.Model):
    class Status(models.TextChoices):
        DRAFT = "draft", "Draft"
        PENDING = "pending", "Pending"
        CONFIRMED = "confirmed", "Confirmed"

    status = models.CharField(max_length=20, choices=Status.choices)

    @property
    def status_badge(self):
        return {
            self.Status.DRAFT: "badge-grey",
            self.Status.PENDING: "badge-orange",
            self.Status.CONFIRMED: "badge-green",
        }[self.status]{% endverbatim %}{% endfilter %}

{% filter force_escape %}{% verbatim %}Use the Wise Design System's Badge component for this. Rules:
- Base markup: Label for a neutral badge.
- Color modifiers (add one, never combine): badge-action, badge-brand (accent, bold);
  badge-grey, badge-orange, badge-green, badge-red, badge-blue (neutral status set -
  deliberately NOT named "success"/"error" so it maps onto any domain's status field).
- For a model's workflow state, add a `status_badge` property on the model that maps
  each status value to a badge-* class name, and render `{{ obj.get_status_display }}`.
  Never build the class by string concatenation in the template (e.g. `badge-{{ status }}`) -
  Tailwind can't see that class at build time and tree-shakes it out, so the badge renders unstyled.
- For a count/notification badge on an icon button, use badge-red, absolutely positioned:
  `{{ count }}` inside a
  `position: relative` button.
- Do not use this for a value the user typed themselves (use the Tag component for that).{% endverbatim %}{% endfilter %}
