Enabling translations

{% filter force_escape %}{% verbatim %}# settings.py
USE_I18N = True
LANGUAGE_CODE = 'en-us'
LANGUAGES = [('en', 'English'), ('fr', 'Français'), ('ar', 'العربية')]
LOCALE_PATHS = [BASE_DIR / 'locale']

MIDDLEWARE = [
    # ...
    'django.contrib.sessions.middleware.SessionMiddleware',
    'django.middleware.locale.LocaleMiddleware',   # must follow SessionMiddleware
    'django.middleware.common.CommonMiddleware',
]{% endverbatim %}{% endfilter %}

Translating the system's own strings

The shipped partials wrap their literals in {% templatetag openblock %} trans {% templatetag closeblock %} — "Filter", "Apply", "Reset filter", "No records.", "Home". Running makemessages over the app picks them up along with your own. 

{% filter force_escape %}{% verbatim %}django-admin makemessages -l fr -l ar
django-admin compilemessages{% endverbatim %}{% endfilter %}

Right-to-left

base.html already sets dir from Django's LANGUAGE_BIDI, so switching to an RTL language mirrors the layout without any template changes. Because the component layer is built from Tailwind's logical properties and flexbox rather than hardcoded left/right offsets, panels, menus and tables flip with it. 

{% filter force_escape %}{% verbatim %}{% endverbatim %}{% endfilter %}
{% lucide "alert-triangle" size=16 cls="callout-icon" %}
Watch for physical offsets in your own markup
A utility like ml-2 or left-0 will not flip. Prefer the logical equivalents (ms-2, start-0) in templates that must support RTL.

Formatting

Dates, numbers and currency use Django's locale-aware formatting (USE_L10N is always on in modern Django). Use {% templatetag openblock %} localize {% templatetag closeblock %} or the date/floatformat filters rather than formatting in Python, so a datatable cell renders correctly per-locale.
