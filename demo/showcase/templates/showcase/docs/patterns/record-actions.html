Actions live in the detail panel

A record's actions sit in the header of its detail panel, next to its title - not in the page's top bar, which keeps only the back link. The first action is a button; every other one is an item of an overflow menu behind a vertical-dots button, with a destructive action last in the danger colour. However many actions a record has (approve, edit, print, archive, delete), the header stays one row, on a phone too.

Your own actions

actions come before Edit (a workflow's transitions: Approve, Submit), more_actions between Edit and Delete (Print, Duplicate). Each is a dict; a visitor lacking the action's own permission never sees it.

def get_context_data(self, **kwargs):
    context = super().get_context_data(**kwargs)
    context['approve'] = [{
        'label': _('Approve'), 'icon': 'check', 'style': 'primary',
        'url': reverse('invoice_approve_view', args=[self.object.pk]),
        'permission': 'billing.approve_invoice',
    }]
    context['print'] = [{
        'label': _('Print'), 'icon': 'printer', 'new_tab': True,
        'url': reverse('invoice_print_view', args=[self.object.pk]),
    }]

An action that changes the record when it runs (archiving, printing that marks a document as sent) is a POST form with a CSRF token, never a link: set 'post': True and, if the view reads it, 'name' / 'value'.

Reference

KeyUse
labelThe text.
urlWhere it goes, or posts to.
iconA Lucide icon name. Defaults to arrow-right.
styleThe button style when it is the first action: primary, secondary (default), danger...
postTrue: a POST form with a CSRF token. name / value are the submit button's.
new_tabOpens in a new tab.
dangerA destructive action: danger colour, a divider above it in the menu.
permissionapp.codename the visitor must hold, or the action is left out.
