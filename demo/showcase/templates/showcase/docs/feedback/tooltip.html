Pure CSS — no positioning library, no script. {% endblock %} {% block doc_body %}

Use cases

  • Labeling an icon-only button so its purpose is clear without adding visible text (e.g. a trash icon needs 'Delete').
  • A short clarification on a truncated value, abbreviation, or a field whose meaning isn't obvious from its label alone.
  • Any hint that should appear on hover AND keyboard focus, with zero JavaScript.
  • Not for content the user needs to read on page load or select/copy text from - a tooltip disappears when hover/focus ends, so use a Callout for anything that must persist.

It is decoration, not an accessible name
data-tooltip renders through a CSS ::after, which assistive technology does not reliably announce, and it never appears on touch devices. The icon button above still needs its own aria-label — the tooltip is a sighted-mouse convenience on top.

Keyboard

The tooltip shows on :focus-within too, so tabbing to the button reveals it — try tabbing through the examples above.

Keep it short

The bubble is whitespace-nowrap, so a long string runs off the side of the screen. Anything longer than a few words belongs in help text or a callout.

Native title as a fallback

For plain text where styling does not matter, the browser's own title attribute needs no component at all — and it does get announced.

- Pure CSS, no script: wrap the trigger element with class="tooltip" and a data-tooltip attribute holding the label text:
  
- It activates on :hover, :focus-visible, AND :focus-within, so keyboard users get the same information as mouse users - never rely on hover alone for an icon-only control's accessible label; also set aria-label (or a visually-hidden span) with the same text, since a CSS tooltip is not read by screen readers.
