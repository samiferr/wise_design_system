The model

A plain adjacency list — a parent foreign key to self. No tree package needed: rendering only ever walks down from the roots, which a prefetch_related handles in two queries. 

{% filter force_escape %}{% verbatim %}class Department(models.Model):
    name = models.CharField(max_length=100)
    parent = models.ForeignKey(
        "self", null=True, blank=True,
        on_delete=models.CASCADE, related_name="children",
    )
    icon = models.CharField(max_length=40, default="building-2")

# In the view - two queries for the whole two-level tree:
Department.objects.filter(parent=None).prefetch_related("children"){% endverbatim %}{% endfilter %}
{% lucide "info" size=16 cls="callout-icon" %}
Depth costs queries
prefetch_related("children") covers one level. For a deep or unbounded tree, chain children__children, or fetch the table once and assemble the nesting in Python — anything is better than a query per node inside the template loop.

Arbitrary depth

Nest .tree-item inside .tree-item-children for deeper levels — the indent guide line comes from a left border, so it stays continuous at every depth. A recursive include keeps the template flat.

Marking the current node

Selection is server-side: add .selected to the current leaf, and open to each ancestor so it is visible on load. This site's sidebar does exactly that by comparing the section and page slugs.
