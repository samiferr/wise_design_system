Class names are the contract

Components are plain CSS classes — .btn, .card, .data-table — not web components or template tags. That means they work in any template, compose with Tailwind utilities, and stay stable when tokens change. Change a token and every component follows; change a class name and you've made a breaking change.

The view mixins

WiseListView, WiseDetailView, WiseCreateView, WiseUpdateView and WiseDeleteView wrap Django's own generic views. They add the context the generic templates need — the filterset, the applied-filter count, the success message — so a full CRUD screen is a handful of attributes. 

{% filter force_escape %}{% verbatim %}from wise_core.mixins import WiseListView, WiseCreateView

class CategoryListView(WiseListView):
    model = Category
    filterset_class = CategoryFilter
    template_name = 'showcase/category/list.html'
    paginate_by = 10


class CategoryCreateView(WiseCreateView):
    model = Category
    form_class = CategoryForm
    template_name = 'showcase/category/form.html'
    success_url = reverse_lazy('category_list_view')
    success_message = 'Category "%(name)s" created.'{% endverbatim %}{% endfilter %}

The generic templates

Each mixin has a matching generic template. You extend it and fill blocks rather than writing the page chrome yourself — that is what keeps every list/detail/form screen in an application consistent.

TemplateBlocks you fill
generic/list_generic.htmllist_icon, list_title, list_actions, list_body
generic/detail_generic.htmldetail_back, detail_title, detail_actions, detail_rows
generic/form_generic.htmlform_back_url, form_title, form_header_actions, plus the form itself
generic/confirm_generic.htmlconfirm_back_url, confirm_rows
